# astrbot_plugin_timer

AstrBot 定时任务插件 —— 让机器人在指定时间自动执行预设指令。

## 功能特性

- 按预设时间（时:分）自动触发指令执行
- 支持通过聊天指令动态新增定时任务
- 可随时启动 / 停止定时任务循环
- 查看当前定时器运行状态与任务列表
- 任务配置持久化保存，重启后仍可通过 `timer start` 加载

## 安装

1. 将本插件文件夹放入 AstrBot 的插件目录（通常为 `data/plugins/`）。
2. 在 AstrBot 控制台中启用插件 `astrbot_plugin_timer`。
3. （可选）在插件配置页面预先填写定时任务。

## 配置说明

插件配置项定义在 `_conf_schema.json` 中，可在 AstrBot 插件管理界面进行设置：

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `tasks` | list | `[]` | 定时任务列表，每项格式为'指令|时间'，例如 '/test|12:00' |
| `switch` | bool | `false` | 定时任务总开关（一般通过指令控制，无需手动设置） |
| `sleep_time` | int | `5` | 轮询周期（秒），即每隔多久检查一次当前时间是否命中任务 |

### tasks 格式说明

每个任务是一个字符串，使用英文竖线 `|` 分隔**指令**和**触发时间**：

```
指令内容|HH:MM
```

- **指令内容**：到点后要让机器人执行的指令文本（如 `/weather`、`今日新闻` 等）
- **时间**：24 小时制，格式为 `HH:MM`，例如 `08:30`、`23:59`

示例：

```json
[
  "/weather|08:00",
  "今日新闻|12:00",
  "/daily|21:30"
]
```

## 指令列表

> 以下所有指令均需要 **管理员（ADMIN）** 权限。

### 1. `timer start` —— 启动定时任务

**作用**：从配置中读取所有定时任务并启动轮询循环。启动后，插件会每隔 `sleep_time` 秒检查一次当前时间，当系统时间（时:分）匹配某个任务的触发时间时，自动将该任务的指令放入事件队列并交由 LLM 执行。

**使用方法**：

```
timer start
```

**说明**：
- 启动时会解析配置中的 `tasks`，格式不合法的任务会被跳过并记录日志。
- 若定时器已在运行，会提示「定时任务已经启动过了」，不会重复启动。
- 任务命中后会额外休眠 60 秒，避免同一分钟内重复触发。

**返回示例**：

```
定时任务已启动，共 3 个任务
```

---

### 2. `timer stop` —— 停止定时任务

**作用**：立即停止定时任务轮询循环，并清空当前内存中的任务列表。

**使用方法**：

```
timer stop
```

**说明**：
- 停止后不会再触发任何定时任务，直到再次执行 `timer start`。
- 已保存到配置中的任务不会被删除，下次启动时仍会加载。

**返回示例**：

```
定时任务已停止
```

---

### 3. `timer stat` —— 查看定时器状态

**作用**：查看当前定时器的运行状态以及已加载的所有定时任务列表。

**使用方法**：

```
timer stat
```

**返回示例**（运行中）：

```
定时器状态：运行中✅
1./weather--08:00
2.今日新闻--12:00
3./daily--21:30
```

**返回示例**（未运行）：

```
定时器状态：未运行💤
```

---

### 4. `timer add` —— 新增定时任务

**作用**：向配置中追加新的定时任务，支持一次添加多个。

**使用方法**：

```
timer add 指令1|时间1 指令2|时间2 ...
```

多个任务之间用**空格**分隔，每个任务内部用**竖线 `|`** 分隔指令和时间。

**示例**：

```
timer add /weather|07:30 晚安|23:00
```

**说明**：
- 新增的任务会写入配置文件（持久化保存）。
- 格式不合法的任务会被跳过。
- **注意**：新增任务后需要重新执行 `timer start`（先 `timer stop` 再 `timer start`）才能让新任务生效，因为任务列表仅在启动时从配置加载。

**返回示例**：

```
新增定时任务 2 项
```

## 使用流程示例

1. **预先配置任务**（可选）：在插件配置页的 `tasks` 中填入：
   ```
   /weather|08:00
   今日新闻|12:00
   ```

2. **启动定时器**：
   ```
   timer start
   ```
   机器人回复：`定时任务已启动，共 2 个任务`

3. **查看状态**：
   ```
   timer stat
   ```

4. **动态添加任务**：
   ```
   timer add 晚安|23:00
   ```
   然后重启定时器使其生效：
   ```
   timer stop
   timer start
   ```

5. **停止定时器**：
   ```
   timer stop
   ```

## 注意事项

- 所有指令均需管理员权限。
- 时间格式必须为 `HH:MM`（24 小时制），例如 `09:05`，不要写成 `9:5`。
- 轮询周期 `sleep_time` 建议不超过 60 秒，否则可能错过整分钟的触发点。
- 同一分钟内的任务只会触发一次（触发后强制休眠 60 秒）。
- `timer add` 新增的任务仅写入配置，需重启定时器后才会加载到运行时列表。
- 插件卸载或停止时会自动终止定时任务循环。
